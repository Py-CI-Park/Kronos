## 병목 재현과 원인

기준 코드에서 `_runs_payload()` 단일 호출은 약 **52.29초**였다. 프로파일링 결과 시간의 대부분은 각 요청마다 불변 Type1 카탈로그를 다시 검증하는 경로에 집중됐다.

- `verify_report_catalog()`가 요청마다 전체 권한·복구·materializer 증거를 재검증했다.
- RFC 8785 정규화가 대형 권한 문서에 반복 적용됐다.
- 매니페스트 탐색이나 네트워크 I/O가 주원인은 아니었다.
- 경로/mtime만 신뢰하는 캐시는 파일 교체 및 reparse 지점 공격에 취약하므로 채택하지 않았다.

## 적용한 1단계 개선

불변 권한 내용에 대해 다음을 만족하는 재사용 계층을 추가했다.

- Python 타입을 보존하는 내용 해시로 `list`와 `tuple` 같은 값을 구분한다.
- RFC 8785 결과 캐시는 총 **96 MiB**를 넘지 않는 LRU로 제한한다.
- 성공한 전체 권한 검증만 작은 LRU에 기록하며 실패 결과는 캐시하지 않는다.
- 잠금 범위 안에서 미스 계산을 수행해 동일 프로세스의 동시 미스를 단일 실행으로 합친다.
- 캐시가 처리할 수 없는 `Mapping` 구현은 기존 검증 경로로 우회한다.
- 검증 중 입력이 바뀌면 실패 폐쇄한다.
- `rfc8785` 부재는 기존처럼 `AuthorityError`로 변환한다.

## 남은 병목과 다음 액션

1. **P0 — 발행 시점 검증 projection/sidecar 설계:** 요청 핸들러에서 대형 권한·복구·materializer 증거를 매번 재구성하지 않도록, 발행 SHA와 결박된 사전 검증 projection을 append-only로 생성한다. 파일 교체·ABA·reparse 방어를 약화시키지 않는 계약 테스트를 먼저 둔다.
2. **P0 — 릴리즈 메타데이터 단일화:** 제품 릴리즈, 셸 표기, API 계약을 한 원본에서 파생하도록 ADR과 계약 테스트를 추가한다.
3. **P1 — Type1 실패 분석 사전등록:** Fresh OOS를 열지 않고 seed, 보상, turnover, 23bp 비용, 셔플 통제군 기여도를 분해한다.
4. **P1 — Type2 독립 가설 사전등록:** Type1 결과를 덮어쓰지 않고 새 acceptance gate와 reused-validation 계획을 먼저 고정한다.
5. **P1/P2 — 보고서 시각화와 WSGI:** 과거 SHA 보고서는 불변으로 두고 새 revision 시각화를 발행하며, 계측 후 loopback 전용 WSGI 운영안을 추가한다.
6. **승인 필요 — Fresh OOS:** 외부 권한과 명시적 승인 전에는 실행하지 않고 계속 `NOT_RUN/no-read`로 유지한다.
