## 2. 영역별 상세 진단 (검증 통과 증거만)

### 2.1 Kronos 파인튜닝 — "왜 실패했는지"의 실체

**측정된 결과** (플래그십 = 26.5h "option D" pred60, 18.8M 샘플):
- 방향정확도 **0.4479 vs 랜덤 0.4493** (엣지 -0.15pp, 랜덤보다 못함) — 681 walk-forward 윈도우
- Top-K net **-0.2041%/trade** (25bp 비용), 누적 **-19.86%**, 전 지평(30/60/120/300s) 비용 게이트 FAIL
- 프로젝트 자체 판정: "training completed but no practical signal" (`docs/stom_2025_full_small_walkforward_eval_dashboard.md:237`)

**확정된 근본 원인 (검증 통과, 순위별)**:

1. **[HIGH·확정] 귀속 실험 부재** — 사전학습 원본(NeoQuasar/Kronos-small)을 동일한 681 윈도우에서 평가한 적이 단 한 번도 없다(`finetune/evaluate_stom_1s_checkpoint.py:352`는 임의 HF id를 받을 수 있으나 실행 기록·아티팩트·문서 어디에도 없음, 저장소 전체 grep 확인). 따라서 "파인튜닝이 실패했다 / 아무것도 안 했다 / 오히려 망쳤다 / 애초에 1초봉에 신호가 없다"를 **구분할 수 없다**. 다음 학습 투자 결정을 막는 단 하나의 미지수.
2. **[HIGH·확정(1건 정정)] 학습 데이터가 캔들 정보를 구조적으로 파괴** — 모든 실제 export가 `close_only`(O=H=L=C 완전 중복, `finetune/qlib_stom_pipeline.py:195-197`), 09:00–09:30만, 1초 그리드 ffill + 거래량 0 채움(:940-947). 6채널 중 3채널이 close의 사본, 검증되지 않은 분포를 사전학습 토크나이저가 인코딩. **정정**: 틱 DB는 초당 1스냅샷뿐이므로 "1초 내 진짜 OHLC"는 애초에 존재하지 않음 — 대안은 이미 구현돼 있으나 미사용인 **1분봉 first/max/min/last 집계**(:600-605, :840).
3. **[HIGH·확정] 플래그십 토크나이저가 검증 미완료** — `tokenizer_run_manifest.json`: `validation_completed: false`, `latest_train_model`(best_model 없음)을 예측기 학습·평가가 그대로 소비. 이전 시도는 99.98%에서 검증 OOM으로 83시간 손실. 재구성 MSE가 존재하지 않아 **토크나이저 열화가 예측기 탓으로 조용히 귀속**되는 구조. 프로젝트 스스로 "재측정 필요"라 기록(`docs/stom_tokenizer_998_recovery.md:67-69`)했으나 미이행.
4. **[MEDIUM] 평가가 비결정적·고분산** — 단일 확률 샘플(T=0.6, sample_count=1), torch 시드 없음. config는 5샘플 권장(`finetune/config.py:200`). 보고된 -0.15pp 엣지가 디코딩 노이즈보다 작을 수 있음.
5. **[MEDIUM] 모델 선택 기준이 토큰 CE 손실뿐** — 손실↔방향정확도 상관 미측정, comet off라 곡선 미보존, 1 epoch·1 seed. 데이터 940배 증가(20k→18.8M)가 방향정확도 0.4444→0.4479 (통계적 무의미).
6. **[MEDIUM] 지평-비용 불일치가 측정된 경제적 사인** — 방향 엣지가 30s→300s에서 39.2%→49.2%로 단조 증가, 300s가 손익분기 최근접(rolling net -0.0052%). 그런데 파인튜닝은 25bp를 못 이기는 60s를 타깃. **다음 최고 수익 실험 = 60s 확장이 아니라 300s 전용 재튜닝.**
7. **[LOW] webui "100%"는 로그 스텝 파싱**이지 모델 품질이 아님 — 99.98% 표시 + 체크포인트 0개 사고가 실재. 준비도 게이트가 체크포인트 파일 존재를 여전히 미확인(`webui/app.py:497-508`).

### 2.2 종가매매 (close-slot) — 0종목 버그의 정확한 해부

**[CRITICAL·확정] 메커니즘** (`stom_rl/daily_close_slot_train.py`):
- `_fit_contextual_bandit_weights`(:203-237)가 **원시(비정규화) 값**으로 피처별 공분산을 계산 후 L1 정규화 → 스케일 ±130만~217만인 `institutional_net_buy`가 스케일 ~0.01인 수익률 피처들을 수치적으로 소멸시키고 **가중치 -0.9999를 독식**. 실측 manifest 가중치·threshold_search.csv 산술 검증 완료(임계값 1,329,614 = 0.9999×|panel min|).
- 결과: "정책"은 사실상 **원시 기관순매수 음수 정렬기**(기관 매도 최대 종목 선호)로 퇴화.
- **올바른 수정 경계**: 데이터셋도 env도 아닌 **fit 내부** — fit에 전달된 train행만으로 per-feature mean/std를 계산·동결하고 스코어링에 적용(윈도우별 refit이므로 누출 안전). 검증된 패턴이 저장소에 이미 존재: `stom_rl/contextual_bandit.py:277-295`(1초 레인).

**[HIGH·확정] "0종목"의 두 번째 층 — 구조적 진실**:
- 임계값 그리드에 "최대값+1" 센티널(아무것도 안 삼)이 포함되고(:326), 모든 거래 임계값의 23bp 차감 평균 보상이 음수라 **센티널(보상 정확히 0)이 argmax로 정당하게 승리**. 타이브레이크도 "적은 선택·높은 임계값" 선호(:528-537).
- **함의**: 정규화를 고쳐도, 23bp를 넘는 알파가 없으면 "안 사는 것"이 in-sample 정직한 최적으로 남을 수 있다. 이를 버그와 구분하려면 ①`chosen_is_no_trade_sentinel` 플래그 노출 ②**강제 top-10 진단 변형** 병행 평가가 필요.

**[HIGH·확정] 학습 곡선이 오늘 생산 불가인 이유**:
- 5회 expanding-refit 라운드가 윈도우별 replay 보상을 **계산 후 폐기**(:747-760은 episode ledger와 feedback 가중치만 보존; episode에는 reward 필드 자체가 없음 — 아티팩트 12개 키 실측 확인).
- 최종 정책을 전 날짜에 적용한 `date_ledgers.json`만 남아 "라운드별 개선" 곡선으로는 **정직하게 쓸 수 없음**.
- 라운드별 평균/누적 보상을 `walk_forward_windows.json`에 영속화하는 **작은 변경 하나** 거리. 단, 5라운드 중 4라운드가 0종목이므로 위 두 수정이 선행돼야 곡선이 0이 아니게 됨.

**[MEDIUM] "contextual bandit"은 부적절한 명명** — 탐색 없음(원샷 공분산 적합), 피드백은 |net_return| 가중이라 큰 손실과 큰 이익을 동일 취급(방향 맹목), 선택이 비면 피드백 자체가 죽음. ts_imb=RULE 라벨링 규율과 동일하게: 탐색을 넣거나, 정직하게 개명하거나.

### 2.3 D4 일봉 RL — "로봇"의 실체

**[CRITICAL·확정]**: 실데이터로 학습된 유일한 알고리즘 = 순수 파이썬 표 기반 Q-러너(상태 = 정수 2개, 액션 5개, 8~12 에피소드×480일, CPU 수 초).
- 기록된 학습 곡선은 **하락**: rolling mean -2.47→-3.35 (8ep), 학습 중 에피소드 equity 0.070→0.029.
- 그리디 정책은 8ep에서 **완전 퇴화**(전 스플릿 거래 0회, NAV 1.0) — Q테이블 0 초기화 + hold 보상 0 + 모든 거래에 비용·페널티 → argmax가 hold로 붕괴하는 구조적 메커니즘 확인. 12ep 변형은 반대로 거래하며 **-42.1% 손실**(val+test).
- D5 게이트는 이를 정직하게 포착: `rl_delta_vs_best_d3 = -0.735`, rule 베이스라인 선택, NO-GO. **(플랫폼의 가드레일은 제 역할을 했다 — 능력 미달 발견이지 은폐 발견이 아님.)**

**[HIGH·확정(정정 포함)]**: SB3 PPO/DQN은 실제 **일봉** 데이터로 학습된 적 없음 — 합성 3종목 픽스처 512 timestep CPU 스모크뿐. (정정: 실제 인트라데이 30분 데이터 5,000 timestep Stage-B 런이 1건 존재하나, 그 자체 판정이 "RECOMMEND ABANDONING RL"이며 일봉 아님.) 100k-step 런들은 별개인 1초 틱 레인.

**[HIGH·확정]**: 런 인벤토리 부풀림 — 명명이 다른 D4 런 디렉토리 6개 중 4개가 동일 seed-7 학습의 재실행(수치 동일). 기록된 최대 D4 실 컴퓨팅 = **5,760 env steps** (전부 스모크 규모). 레인은 2026-06-18 이후 휴면.

**[LOW·핵심 수식 결함]**: `daily_portfolio_env.py:366-372`의 `equity *= 1 + reward`에서 reward에 **노출·집중·churn·드로다운 페널티가 이미 포함** → 텔레메트리의 "equity"는 NAV가 아니라 페널티 복리 수량. **Q-러너가 개선되더라도 이 수식으로는 equity 곡선이 우상향할 수 없다.** 진짜 NAV(`info['net_return_after_cost']` 복리)는 per-step으로 존재하나 어떤 곡선 아티팩트도 그것을 그리지 않음.

기타: D4 런이 factory registry에 0행(거버넌스 부재), MLflow 심은 "NOT WIRED"이고 아무도 import 안 함, GPU 존재하나 미사용(`device="cpu"` 고정), 8ep↔12ep 정책 급반전에 대한 시드 민감도 연구 부재.

### 2.4 라이브 스트리밍 — 90%는 이미 지어져 있다

**이미 완성·배선됨 (이전 통념 정정)**: `RlLiveEventWriter`(JSONL) → `GET /api/rl/runs/<run>/events` → `LiveRlEventsCard.svelte`가 **4초 폴링으로 reward/equity 라이브 차트를 이미 렌더**하며(LIVE/IDLE 펄스 pill 포함), `RunSelector`는 **멀티런 오버레이를 이미 지원**한다. v3 plan P7은 구현 완료 상태.

**남은 진짜 갭 (전부 확정)**:
1. **[HIGH] `daily_rl_train.py` 이벤트 미방출** → D4 레인 라이브 차트가 구조적으로 영구 공백. 훅 위치 확정: 에피소드 루프 :663-677, 평가 루프 :729-731, rid를 `run_and_write_daily_rl`(:1716)로 호이스트.
2. **[HIGH] `daily_close_slot_train.py` 이벤트 미방출** → walk-forward 라운드·일별 수익 비가시. 훅: 윈도우별 :757-760, 날짜별 :399. **주의**: 베이스라인 평가(no_trade/shuffle/momentum/D3)도 같은 함수를 호출하므로 반드시 밴딧 호출에만 방출하거나 `algorithm='rule_baseline'` 태깅(RULE을 RL로 표기 금지 가드레일).
3. **[HIGH] 두 daily 런 디렉토리가 `/api/rl/runs`에서 미발견**(`ARTIFACT_SIGNATURES` 10종에 미부합 → artifact_type 'unknown' → 목록 제외). 전송은 이미 관대함(발견만이 블로커). 수정: `webui/rl_dashboard_files.py:17-28` 시그니처 2건 추가(P7 동결 목록에 미포함 확인됨).
4. **[MEDIUM]** rid가 학습 종료 후에만 결정 + 비어있지 않은 디렉토리 FileExistsError → 학습 중 라이브 파일 기록 불가(호이스트+허용목록으로 해결). 오버레이 x축이 인덱스 정렬이라 스텝 간격이 다른 런 비교 시 조용히 어긋남(value축+튜플로 해결). `/events` 커서 부재는 daily 레인 볼륨에선 문제 아님(추후 Gate-A 게이트로 업그레이드).

### 2.5 RL 가시성 UX — "없는 게 아니라 숨어 있다"

**[HIGH·확정]** env→action→reward 루프 **시각 자료**가 모든 랜딩 화면에서 기본 은닉: 유일한 루프 SVG는 고아에 가까운 가이드 탭의 접힌 Disclosure 안(요약문에 '다이어그램'이란 단어조차 없음). Mission Control·RL 탭은 정적 'NO-GO' 문자열과 16개 접힌 Disclosure만.

**[HIGH·확정]** "에이전트가 뭘 했나"가 마지막 마일에서 유실: 이벤트 스키마는 `action_name`(hold/buy/sell)을 모든 스텝에 실어 브라우저까지 도달시키는데, `LiveRlEventsCard`는 reward/equity만 렌더. 액션 피드/테이블/집계가 전무.

**[정정(REFUTED→MEDIUM)]** "나아지는지 아무 데서도 안 보인다"는 과장 — `LiveRlEventsCard`는 기본 노출이며 4초 갱신 reward/equity 차트 + LIVE/IDLE pill로 "살아있는지"는 구분 가능. **정확한 갭**: ①에피소드 횡단 **장기 학습 곡선**(reward-per-episode 추이)이 기본 화면에 없음 ②콜드 로드 기본 런이 이벤트 없는 RULE 아티팩트라 첫 화면이 IDLE 공백.

**[MEDIUM]** 실데이터 리플레이(상태·액션·보상 분해 프레임, fail-closed)는 이미 백엔드가 생산(`daily_ohlcv_dashboard.py:5336-5435`)하나 3중 게이트(섹션 버튼→Disclosure→기본 일시정지 타이머) 뒤에 있고, 항상 보이는 SVG는 하드코딩 정적 텍스트만 표시. **[MEDIUM]** '0종목 정규화 버그'라는 정직한 상태가 각주 11단어일 뿐 화면 상태가 아님 — close-slot 카드는 원인 설명 없는 빈 테이블만 노출.

## 6. 정직한 경계 — 약속할 수 있는 것과 없는 것

**만들 수 있는 것 (엔지니어링 약속)**:
1. 학습이 일어나는 동안 일별 수익·보상·에쿼티가 **실시간으로 움직이는 그래프** (R2+S1)
2. 버그 없는 정직한 학습 루프 — 종목을 실제로 선택하고, 보상이 기록·영속화되는 시스템 (R1+R2)
3. **개선되면 개선이 보이고, 안 되면 안 되는 게 보이는** 대시보드 (S1 에피소드 추이 + NON_IMPROVING 자가 판정)
4. GPU를 실제로 쓰는, 스모크가 아닌 규모의 RL 학습 1회전 (R3)

**약속할 수 없는 것 (연구 결과이지 엔지니어링이 아님)**:
- "우상향하는 수익 그래프"의 **보장**. 23bp 비용 하에서 알파가 없으면 "아무것도 안 사는 것"이 정직한 최적일 수 있으며, 그것도 유효한 연구 결과다. 현재까지의 측정(D5 NO-GO, rl_delta -0.735, Kronos 방향정확도 랜덤 이하)은 이 가능성을 배제하지 않는다.
- 본 플랫폼의 false-lock 7종(실거래·브로커·주문·계좌·페이퍼·모델빌드·수익주장)은 전 단계에서 불변이다. 학습 곡선 상승은 **train-replay 내 보상 개선**으로 정직하게 라벨링되며, OOS 수익성 주장으로 표기되지 않는다.

1. `npm run build` 0 오류 (dist 갱신) — 대시보드 변경 시
2. 관련 pytest 그린 (기존 마커·가드레일 계약 불변: `data-*`, WATCH/NO-GO, D0/D1/D5, read-only DB, `000250`, ts_imb=RULE, 23bp)
3. 실브라우저 캡처 (light/dark 모두) — 화면 변경 시
4. 학습 변경 시: 사전등록 문서 + 스모크 런 → 아티팩트/이벤트 스키마 검증 → 풀 런
5. RULE 베이스라인이 RL로 표기되지 않음을 자동 테스트로 고정
